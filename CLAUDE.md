# Minus Chrome extension — agent orientation

MV3 extension that detects ads with an **in-browser vision model** (LFM2.5-VL via
transformers.js/ONNX on WebGPU) and covers them with Spanish flashcards. Sibling
of the `minus` HDMI device; models are trained in `/home/ubuntu/training`
(see that repo's `docs/iteration-log.md` for the full model campaign).

## Layout

| Path | What |
|---|---|
| `extension/content.js` | All frames: static display scan, `<video>` sampler, iframe motion sampler, overlay lifecycle, **decision tiering** (see below) |
| `extension/background.js` | SW: screenshot capture (rate-limited), classify routing, badge/per-tab counter, anonymous-snapshot queue+upload, per-engine threshold lookup |
| `extension/offscreen.js` | Offscreen document: engine loading (WebGPU), classify loop, benign-error muting, Windows `powerPreference` strip |
| `extension/models_catalog.js` | Dependency-free catalog logic shared by offscreen + build scripts + tests. `FALLBACK_CATALOG` here is the **tracked** source of truth (models/ is gitignored) |
| `extension/models/` | Packaged engines (gitignored, ~GBs). `index.json` generated by `build_model_index.mjs` — curated entries (key/label/default/**thresholds**) are preserved across regenerations |
| `extension/welcome.html/js`, `onboarding/` | First-run onboarding (opened on install; real annotated screenshots) |
| `tests/` | Fast regression (`npm test`, no GPU) + GPU-backed suites (soak, functional) via `tests/harness.mjs` |
| `package.mjs` | Release zip: extension contents at archive ROOT, default engine's weights only (~400 MB) |

## Decision tiering (content.js) — the precision architecture

1. **Ad-context elements** (iframe / ad-hint ancestor): block at `p_ad ≥ CTX_BLOCK_P`.
2. **Bare `<img>`/`<div>`**: only if near-standard IAB size AND not near-square
   (`isSquarish` 0.87–1.15 → product tiles/editorial, never blocked) AND
   `p_ad ≥ BARE_BLOCK_P`. Unloaded imgs (`naturalWidth===0`) skipped (dark-placeholder FP).
3. **Video/iframes**: `is_ad` at the user threshold with 2-verdict hysteresis.

`CTX_BLOCK_P`/`BARE_BLOCK_P` default 0.60/0.88 but are **per-engine**: catalog
entries may carry `thresholds: {ctx, bare}` (background resolves the active
engine's entry and sends it with `minus:settings`). Iter 24 ships 0.35/0.75 —
justified by benchmark separation, validated by a live A/B (+33 % coverage,
precision held). New models should ship their own operating point; pick it from
the PR-curve on `training/data/web_ad_bench` scores, never inherit 0.5 or a
predecessor's gates (see training repo `docs/iter24-strategy.md`).

**Capture pipeline nuance:** anonymous-snapshot crops record *model verdicts*,
which is NOT the same as user-visible overlays — structural gates suppress many
model-level positives (e.g. Nike product shots at p 0.96 produce crops but no
covers). When reviewing soak captures, judge user-visible precision by the
overlay site list + screenshots, and use crops for model-level analysis.

## Commands

```bash
node build.mjs            # bundle ORT+transformers.js into extension/dist/ + regen model index
npm test                  # fast regression, no GPU, no model download
npm run package           # release zip -> dist-release/minus-extension-v<version>.zip
# GPU soak (real model, ~230 sites, anonymous capture to a local sink):
ENGINE=lfm node tests/iteration_soak.mjs <tag> <minutes>
```

Release flow: bump `extension/manifest.json` version → `npm test` → commit/push →
`npm run package` → `gh release create v<X.Y.Z> dist-release/…zip`. The zip must
have `manifest.json` at its ROOT (no wrapper dir) and only the default engine.

## Hard-won gotchas (do not relearn these)

- **Playwright evaluates on MV3 contexts HANG, not reject.** Chrome idle-kills
  the extension SW; an evaluate on a stale handle blocks forever, and a wedged
  renderer does the same for page/frame evaluates. Every SW poll must re-acquire
  the handle (`ctx.serviceWorkers()[0]`) and be `Promise.race`d against a hard
  timeout; long site loops need a per-site watchdog that force-closes the page
  (see `tests/harness.mjs waitForEngine` + `tests/iteration_soak.mjs`). This
  froze four consecutive soaks before being fixed everywhere.
- **`chrome.runtime.sendMessage` never delivers to the sender's own context** —
  a SW can't message itself; test message handlers from a popup/extension page.
- **Tegra/Dawn WebGPU flakes on cold launch** (~50 %): browser-level adapter can
  pass while the offscreen document's fails. Retry the whole launch (the soak
  self-heals ×3). Headless WebGPU needs `--enable-unsafe-webgpu
  --ignore-gpu-blocklist --use-angle=vulkan --enable-features=Vulkan
  --disable-vulkan-surface` and the full chromium build, not headless shell.
- **`pkill -f <pattern>` can match the invoking shell's own command line** and
  SIGTERM your session (exit 144). Kill by exact PID or `pkill -x chrome`.
- Chrome caches the MV3 SW script in the profile — the harness scrubs
  `Default/Service Worker` per launch or you run STALE background.js.
- Windows logs a `powerPreference`-ignored warning from INSIDE
  `requestAdapter()`; console filters can't catch it — offscreen.js strips the
  option at the `navigator.gpu.requestAdapter` choke point (Windows only).
- The engine needs ~1–2 GB; `device_map`-style multi-engine dirs in `models/`
  are dev-only — `package.mjs` excludes all but the default.

## Testing conventions

- `npm test` = catalog/occlusion/powerPref/branding/badge suites — keep green;
  extension-loading tests get their own profile dirs to avoid lock contention.
- Soaks write per-site coverage + captured crops to `tests/screenshots/<tag>/`;
  review crops as contact sheets before drawing precision conclusions.
- Live-soak precision ≥80 % is the ship bar for engine/threshold changes;
  benchmark recall alone is NOT a ship gate (Iter 22 lesson — passed bench,
  43 % live precision).
